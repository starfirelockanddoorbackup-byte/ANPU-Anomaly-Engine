Project Vision & Core Objectives

ANPU is an autonomous, air-gapped, and local-first telemetry monitoring engine built under Matthews Operations Lab. In an era of increasing infrastructure fragility, supply chain shocks, and cyber-physical convergence threats, traditional cloud-dependent security tools fail the moment wide-area communication links degrade.

ANPU serves as the sensory and diagnostic layer for resilient edge nodes. It ingests multi-domain telemetry vectors entirely offline, processing data locally without cloud dependencies, API subscriptions, or data leakage.

What Makes ANPU Unique?

  • Zero-Cloud Footprint: Runs entirely on sovereign hardware using local SQLite data storage and standard Python libraries.
  • Multi-Domain Convergence: Correlates disparate vectors—such as BGP routing anomalies, grid frequency jitter, SCADA probing, GNSS jamming, and media narrative divergence—into a single unified threat index.
  • Unsupervised Intelligence: Employs scikit-learn Isolation Forest models to establish hyper-repetitive baselines and flag structural deviations without requiring massive cloud retraining datasets.
  • Human-in-the-Loop Governance: Strictly enforces an out-of-band operator triage gate, ensuring automated systems act solely as an advisory oracle rather than executing unverified control-plane shutdowns.

Operational Philosophy

Industrial Control Systems (ICS) and critical infrastructure networks are hyper-repetitive and deterministic. ANPU is designed around the Asymmetric and Austere framework—providing maximum situational awareness with minimal hardware overhead.

By keeping the monitoring node passive (mirroring SPAN ports or hardware data diodes), ANPU identifies early-stage reconnaissance and pre-positioning lateral movement long before disruptive payloads can be deployed.

Behind the Scenes: The "Hacker Hunter" Architecture

ANPU operates on a strict separation of concerns between deterministic data ingestion, unsupervised machine learning, and human-governed intervention.

  • Step 1: Passive Ingestion (`anpu_ingest.py` & `anpu_ics_sim.py`): Scripts aggregate multi-domain metrics and industrial Modbus register polls into a local SQLite database (`anpu_telemetry.db`) without interacting with control planes.
  • Step 2: Unsupervised Scoring (`anpu_anomaly_engine.py`): A scikit-learn Isolation Forest model constructs a feature matrix from historical cycles, computing anomaly path scores and the aggregated Hybrid Threat Index (HTI).
  • Step 3: Network Hardening & Data Diodes: In a production physical deployment, telemetry is fed via unidirectional optical data diodes or passive SPAN switch ports, ensuring zero return pathways from the analytics node back into industrial networks.
  • Step 4: The Out-of-Band Human Gate: If threat thresholds are breached, the system halts automated execution, presenting mandatory triage prompts to human operators to prevent false-positive automation cascades.

Beta Testing Onboarding & Deployment Guide

ANPU is currently open for beta testing among trusted engineers, homelab operators, and infrastructure security professionals. Because the system is built with zero external dependencies, deployment takes under two minutes.

Quick-Start Instructions (Windows Local Node):

  • Clone or download the repository from GitHub.
  • Ensure Python is installed with required libraries (`pip install pandas scikit-learn`).
  • Double-click run_anpu.bat to execute the automated ingestion, ICS simulation, and anomaly scoring cycle.
  • Review the terminal readout and complete the operator triage prompt.

Targeted Beta Profiles:

  • Homelab & Developer Track: Focus on testing the zero-cloud footprint, local SQLite persistence, and lightweight Python architecture.
  • OT & ICS Security Track: Audit the passive sensor logic, data-diode architectural boundaries, and advisory-only triage flow.
  • Resilience & Operations Track: Evaluate degraded-bandwidth situational awareness and localized reporting speed.
